# PLAN.md — План разработки MVP кросс-платформенного клиента Telegram

> **Прогресс (август 2026):** этапы 1–5 MVP завершены. **§6.2** (список чатов и организация) закрыт. Актуальный чеклист — [TODO.md](TODO.md). Документация — [docs/](docs/), список чатов — [docs/CHATS.md](docs/CHATS.md).

## 1. Цель
Создать собственный кросс-платформенный (Windows, macOS, Linux, Android, iOS) клиент Telegram на Flutter с модифицированным ядром TDLib, способным обходить блокировки РКН с помощью:
- рандомизированного TLS ClientHello (Fake TLS)
- фрагментации и маскировки трафика
- поддержки собственных прокси (PhantomProxy и StealthGate) с автоматическим переключением между ними.

Приложение должно давать полный контроль над кастомизацией интерфейса и сетевой логикой.

## 2. Архитектура

```
┌─────────────────────────────────────────────────────┐
│                Flutter UI (Dart)                    │
│  - кастомизируемые темы, виджеты, анимации         │
│  - экраны авторизации, чатов, настроек              │
└─────────────────────┬───────────────────────────────┘
                      │ FFI (Dart ↔ C++)
┌─────────────────────▼───────────────────────────────┐
│              TDLib (модифицированный)                │
│  - стандартная логика Telegram API                   │
│  - ПАТЧИ для обхода DPI:                            │
│    • рандомизация ClientHello (под Chrome/Firefox)  │
│    • фрагментация первого пакета                    │
│    • варьирование размеров TLS-записей             │
│    • подмена fingerprint TLS-стека                  │
└─────────────────────┬───────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────┐
│     Прокси-серверы (на ваших VPS)                   │
│  - Основной: PhantomProxy (Go) на VPS в РФ          │
│  - Резервный: StealthGate (Rust) на VPS в РФ       │
│  - Backend (EU): StealthGate (опционально)          │
└─────────────────────────────────────────────────────┘
```

## 3. Этапы разработки (MVP)

### Этап 0: Подготовка окружения и инфраструктуры
| Задача | Детали |
|--------|--------|
| Настроить VPS в РФ (2 шт.) | Установить Docker / системные пакеты, открыть порты |
| Развернуть PhantomProxy | Собрать из исходников или скачать бинарник, запустить с конфигом |
| Развернуть StealthGate (Front/Back) | Настроить сплит-режим: Front на РФ, Back на EU |
| Проверить работоспособность прокси | Подключиться через официальный клиент вручную |
| Получить API credentials | Зарегистрировать приложение на my.telegram.org → api_id, api_hash |
| Установить Flutter SDK | Версия ≥3.22, настроить Android/iOS/Desktop окружения |
| Установить инструменты сборки TDLib | CMake, GCC/Clang, Ninja, зависимости (OpenSSL, zlib) |

### Этап 1: Создание базового Flutter-проекта и интеграция TDLib
| Задача | Детали |
|--------|--------|
| Создать проект | `flutter create --org com.yourcompany your_telegram_client` |
| Добавить зависимости | `tdlib_library` (или ручной FFI-биндинг), `provider`/`riverpod` для стейта, `dio` для HTTP (опционально) |
| Написать обёртку TDLib | Класс `TdlibClient` с инициализацией, отправкой команд, обработкой обновлений |
| Реализовать авторизацию | Поток: запрос номера → код → пароль (если есть) → получение `authorizationState` |
| Сделать простой UI | Экран ввода номера, экран ввода кода, список чатов (базовый) |
| Интегрировать логирование | Включить логи TDLib для отладки |

**Итог этапа:** Приложение может авторизоваться и показать список чатов (без модификаций обхода).

### Этап 2: Модификация TDLib для обхода DPI
| Задача | Детали |
|--------|--------|
| Склонировать исходники TDLib | `git clone https://github.com/tdlib/td.git` |
| Изучить сетевой стек | Найти файлы: `td/telegram/NetQuery.cpp`, `td/telegram/Transport.h`, `td/net/HttpProxy.cpp` и др. |
| Реализовать рандомизацию ClientHello | Вдохновиться кодом **ZaStoGram** и **TeleMT**:<br>- Создать массив профилей (Chrome, Firefox, Yandex, Safari)<br>- При каждом подключении выбирать случайный профиль<br>- Генерировать случайные параметры (CipherSuites, Extensions) |
| Добавить фрагментацию пакетов | Разбивать первый TLS-пакет на несколько частей (имитация TCP-сегментации) |
| Варьировать размеры TLS-записей | Изменять размеры последующих записей в пределах допустимого |
| Подмена TLS-стека | Использовать библиотеку `utls` (если возможно) или вручную менять fingerprint |
| Собрать модифицированный TDLib | Собрать под все платформы (или хотя бы под Windows и Android для теста) |
| Протестировать с прокси | Подключиться через PhantomProxy и StealthGate, убедиться в прохождении блокировок |

**Итог этапа:** Трафик клиента не распознаётся DPI как Telegram, прокси работают стабильно.

### Этап 3: Интеграция прокси и автоматическое переключение
| Задача | Детали |
|--------|--------|
| Добавить поддержку прокси в TDLib | Использовать встроенные методы `addProxy`, `enableProxy`, `removeProxy` |
| Настроить два прокси | Добавить PhantomProxy как основной (приоритетный), StealthGate как резервный |
| Реализовать проверку доступности | Использовать `pingProxy` с таймаутом 5 секунд |
| Написать логику переключения | При ошибке соединения или таймауте – переключить на следующий прокси в списке |
| Добавить индикацию текущего прокси в UI | Отображать иконку/статус в настройках или на главном экране |
| Сделать возможность ручного переключения | Экран настроек со списком прокси и возможностью включить/отключить |

**Итог этапа:** Клиент автоматически переключается на рабочий прокси при недоступности основного.

### Этап 4: Полировка интерфейса и кастомизация
| Задача | Детали |
|--------|--------|
| Разработать систему тем | Поддержка светлой/тёмной темы, возможность выбора акцентного цвета |
| Добавить базовые функции чата | Отправка текстовых сообщений, просмотр медиа (фото, видео) |
| Добавить уведомления | Локальные push-уведомления (через `flutter_local_notifications`) |
| Реализовать настройки | Экран с возможностью смены прокси, темы, выхода из аккаунта |
| Сделать адаптивный дизайн | Под разные размеры экранов (мобильные и десктопные макеты) |

**Итог этапа:** Приложение имеет полноценный, приятный интерфейс и базовые функции чата.

### Этап 5: Сборка и тестирование на всех платформах
| Задача | Детали |

| Написать тесты | Юнит-тесты для логики прокси, интеграционные тесты для авторизации |
| Исправить найденные баги | Сбор обратной связи от тестирования |

**Итог этапа:** Приложение готово к релизу на всех платформах.

## 4. Ресурсы и инструменты

### Репозитории для вдохновения
- **Модификации TDLib:**
  - [ZaStoGram_desktop](https://github.com/youtubediscord/ZaStoGram_desktop) – реализация Fake TLS, фрагментации.
  - [TeleMT/tdlib-obf](https://github.com/telemt/tdlib-obf) – продвинутая обфускация.
- **Flutter-клиенты:**
  - [Mithka](https://github.com/iebb/mithka) – полноценный клиент на Flutter + TDLib.
  - [telega2](https://github.com/festeh/telega2) – пример интеграции TDLib с FFI.
- **Прокси:**
  - Ваши собственные – [StealthGate](https://github.com/RioTwWks/StealthGate) и [PhantomProxy](https://github.com/RioTwWks/PhantomProxy) – использовать как серверную часть.

### Библиотеки и пакеты Flutter
- `tdlib_library` – упрощает интеграцию TDLib (можно форкнуть и заменить на свою сборку).
- `provider` или `riverpod` – управление состоянием.
- `dio` – для HTTP-запросов (если понадобится).
- `flutter_local_notifications` – для уведомлений.
- `shared_preferences` – для хранения настроек.
- `path_provider` – для путей к файлам базы.

### Сборка TDLib
Официальная инструкция: [tdlib.github.io/td/build.html](https://tdlib.github.io/td/build.html)

## 5. Риски и их смягчение

| Риск | Смягчение |
|------|-----------|
| Модификации TDLib перестанут работать после обновления протокола | Вести собственный форк TDLib и следить за обновлениями официального репозитория. |
| Блокировка IP-адресов ваших VPS | Использовать несколько VPS в разных подсетях, а также схему Front/Back (StealthGate) – если заблокируют Front, быстро заменить его. |
| Сложность сборки TDLib под все платформы | Использовать CI/CD (GitHub Actions) для автоматической сборки. |
| Ошибки в реализации DPI-обхода | Тщательно тестировать на реальных сетях провайдеров, использовать логи DPI-симуляторов (например, `dpi-tools`). |
| Утечка API-ключа | Хранить `api_hash` не в коде, а получать через защищённый бэкенд или генерировать динамически. |
